# Руководство по разработке и вызову пайплайна (PIPELINE.md)

В этом документе описана организация рабочего процесса для создания компонентов и страниц лендинга Astro SSG с использованием специализированных скиллов Antigravity.

---

## 🧭 Обзор команд и префиксов

Для сохранения чистоты контекста и предотвращения ошибок кодогенерации вызывайте скиллы через префиксы сообщений:

| Префикс / Команда | Активный скилл                        | Назначение фазы                    | Результат работы                                                                                      |
| :---------------- | :------------------------------------ | :--------------------------------- | :---------------------------------------------------------------------------------------------------- |
| `/plan <задача>`  | `task-planner`                        | Архитектурная декомпозиция         | Чеклист, `interface Props`, desktop/mobile план, вопросы. **Код не пишется!** Срабатывает Stop-point. |
| `/scout <вопрос>` | `pattern-scout`                       | Исследование Zero-JS паттернов     | Анализ решений (FOUC, smooth scroll, popover, dialog), влияние на Core Web Vitals.                    |
| `/build [правки]` | `astro-architect` + `design-enforcer` | Реализация компонента и стилизация | Файл `.astro` в `src/components/`, стили по токенам из `DESIGN.md`, острова с директивами `client:*`. |
| `/review`         | `code-reviewer`                       | Валидация и статический анализ     | Автоматический запуск `lint`, `fmt:check`, `build` через `pnpm`. Исправление ошибок.                  |
| `/commit`         | `smart-commit`                        | Фиксация изменений в Git           | Автономное разделение на 1 или N атомарных коммитов на английском (Conventional Commits).             |

## 🚀 Пошаговый сценарий работы (End-to-End пример)

### Шаг 1: Планирование без кода

Вы отправляете запрос:

> `/plan Создай секцию Pricing с тремя тарифными планами и переключателем месяц/год`

Агент активирует скилл **`task-planner`**:

1. Сверяется с `AGENTS.md` и `DESIGN.md`.
2. Описывает семантическую разметку (`<section id="pricing">`, `<button>` для переключателя).
3. Формирует `interface Props`.
4. Планирует **Desktop-First** композицию (3 колонки) и глубоко прорабатывает мобильное поведение:
   - Как перестраивается на смартфонах (свайп-карусель на CSS scroll-snap или вертикальный стек).
   - Touch-таргеты не менее 44x44px.
   - Упрощение/отключение hover-анимаций для мобильных тач-устройств.
5. Фиксирует **Stop-Point**:
   ```markdown
   🛑 [STOP-POINT: ОЖИДАНИЕ ПОДТВЕРЖДЕНИЯ ПЛАНА]
   ```
   **Агент не пишет код и ждет вашей реакции.**

---

### Шаг 2 (Опционально): Исследование паттерна

Если переключатель тарифов месяц/год требует решения без лишнего JS, можно уточнить:

> `/scout Как лучше сделать переключатель тарифов месяц/год без гидратации React?`

Агент активирует **`pattern-scout`**:

- Предложит решение на нативном CSS `:has()` / скрытом радиобаттоне либо ультралегком инлайн-скрипте без загрузки тяжелого React-острова.

---

### Шаг 3: Реализация (Build & Style)

Вы подтверждаете план:

> `/build План утвержден, реализуй компонент` (или просто: `Приступай`)

Агент последовательно применяет:

1. **`astro-architect`**:
   - Создает `src/components/sections/Pricing.astro`.
   - Задает семантическую структуру, строго типизированные пропсы.
   - Оптимизирует иконки и изображения через `astro:assets`.
2. **`design-enforcer`**:
   - Применяет цвета, отступы и радиусы строго по `DESIGN.md`.
   - Проверяет отсутствие «магических» классов вроде `p-[19px]`.
   - Добавляет адаптивные медиа-запросы и `@media (prefers-reduced-motion: reduce)`.

---

### Шаг 4: Автоматическая валидация (Review)

Сразу после сохранения компонента агент автоматически подключает **`code-reviewer`**:

1. Запускает команды:
   ```bash
   pnpm run lint
   pnpm run fmt:check
   pnpm run build
   ```
2. Проверяет семантику (наличие `aria-*`, правильность тегов).
3. При обнаружении ошибок линтера или типов — агент самостоятельно вносит исправления.
4. Предоставляет итоговый отчет с галочками соответствия.

---

### Шаг 5: Фиксация изменений в Git (`smart-commit`)

Вы отправляете запрос:

> `/commit` (или _«Закоммить изменения»_)

Агент активирует **`smart-commit`**:

1. Анализирует `git status` и `git diff`.
2. Автономно принимает решение: сделать **1 коммит** (если изменение атомарно) или **разбить на несколько коммитов** (например, отдельно базовые компоненты и секция).
3. Генерирует сообщения строго на английском языке по стандарту Conventional Commits (например: `feat(pricing): add pricing section with zero-js toggle`).
4. Выполняет `git commit` с соблюдением pre-commit хуков (запрет на флаг `--no-verify`).

## ⚠️ Памятка по ограничениям (Guardrails)

- **Пакетный менеджер**: Только `pnpm`. Команды `npm`, `yarn`, `bun` запрещены.
- **Изображения**: Запрещен тег `<img>`. Только `astro:assets`.
- **Заголовки**: `<h1>` только в `Hero.astro`.
- **Острова**: `client:load` только для критического интерактива первого экрана. Для остального — `client:visible` или нативный `.astro`.
