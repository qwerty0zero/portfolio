## 🏛️ Ключевые архитектурные правила (Guardrails)

### 1. Zero JS by default

- Все секции лендинга (Hero, Features, Social Proof, FAQ, Pricing, Footer) реализуются **исключительно как нативные `.astro` компоненты**.
- Не подключайте клиентский JavaScript, если задача решается разметкой, CSS-стилями или нативными API браузера.

### 2. Жесткие правила клиентских островов (Islands Architecture)

Интерактивный компонент на внешнем фреймворке (React, Vue, Svelte) создается **только при объективной невозможности решить задачу в `.astro`**. В случае создания острова действует жесткая матрица директив:

| Директива        | Где и когда разрешена                                                  | Назначение                                                                                                                                       |
| :--------------- | :--------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------- |
| `client:visible` | **Директива по умолчанию** для всех островов ниже первого экрана       | Загружает и гидрирует JS только при появлении компонента во viewport пользователя.                                                               |
| `client:idle`    | Для второстепенного фонового интерактива и виджетов                    | Гидрирует компонент после завершения первичной загрузки страницы (`requestIdleCallback`).                                                        |
| `client:load`    | **СТРОГО ЗАПРЕЩЕН**, кроме критических элементов первого экрана (Hero) | Блокирующая загрузка JS вместе с первоначальным рендером страницы. Допустима только при острой необходимости немедленной интерактивности в Hero. |

### 3. Оптимизация медиа (Запрет голых `<img>`)

- **Категорически запрещено** использовать прямой тег `<img>`.
- Все изображения рендерятся строго через компонент `astro:assets`:
  ```astro
  ---
  import { Image } from 'astro:assets';
  import heroImg from '../../assets/hero.png';
  ---
  <Image
    src={heroImg}
    alt="Описательный содержательный alt-текст"
    width={1200}
    height={800}
    loading="eager" // только для Hero, для остальных lazy по умолчанию
  />
  ```
- Для адаптивных форматов (AVIF, WebP) и разных экранов использовать `<Picture />`.

### 4. Семантический контракт и SEO

- **Ровно один `<h1>` на страницу**: размещается исключительно в первом экране (секция Hero). В остальных секциях используются `<h2>`, `<h3>` и т.д.
- **Логическая иерархия тегов**:
  - Страница оборачивается в `<main>`.
  - Верхнее меню — в `<header>` и `<nav>`.
  - Каждая отдельная секция — в `<section id="..." aria-labelledby="...">`.
  - Подвал — в `<footer>`.
- **Интерактивные элементы**:
  - Кликабельное действие, не меняющее URL -> `<button type="button">`.
  - Переход по URL / якорной ссылке -> `<a href="...">`.
  - Запрещено вешать `onClick` на `<div>` или `<span>`.

## 📁 Стандарт размещения компонентов

Код организуется строго по дереву проекта:

```text
src/
├── assets/          # Изображения, векторная графика, локальные ассеты
├── components/
│   ├── ui/          # Базовые переиспользуемые атомы (Button.astro, Badge.astro, Card.astro)
│   └── sections/    # Секции страниц (Hero.astro, Pricing.astro, FAQ.astro)
├── layouts/         # Базовый Layout.astro (мета-теги, слоты)
└── pages/           # index.astro и маршруты
```

  <div class="container">
    <div class="section-header">
      <h2 id={`${id}-heading`} class="section-title">{title}</h2>

      <slot />

  </div>
