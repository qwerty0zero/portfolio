# Скилл: pattern-scout (Поиск решений и бенчмаркинг паттернов)

Цель скилла — гарантировать, что для каждой нетривиальной UI/UX задачи выбрано наиболее быстрое, доступное и минималистичное решение с соблюдением принципа **Zero JS by default** и контракта [AGENTS.md](file:///c:/Users/Admin/WebstormProjects/portfolio/AGENTS.md).

---

## 🎯 Основная философия

1. **Native Web First**: Если задачу можно решить нативным HTML5 или современным CSS — фреймворки и JavaScript подключать запрещено.
2. **Zero FOUC (Flash of Unstyled Content)**: Критические состояния (например, активная тема оформления) должны разрешаться синхронным блокирующим инлайн-скриптом минимального размера в `<head>` до первой отрисовки DOM.
3. **Бюджет производительности**: Любое стороннее решение оценивается по влиянию на Core Web Vitals (LCP, CLS, INP) и мобильный рендеринг.
4. **Desktop-First + Mobile Graceful Handling**: Паттерн должен быть эффективен на десктопе и плавно деградировать/адаптироваться на мобильных экранах без лагов анимации и утечек памяти.

## Каталог типовых Zero-JS / Light-JS паттернов

При вызове скилла агент сверяется со следующими проверенными паттернами:

### 1. Переключение темы (Dark/Light Mode) без FOUC

- **Решение**: Минимальный инлайн-скрипт (до 5 строк) в `<head>` внутри `Layout.astro`, читающий `localStorage` и `prefers-color-scheme` и синхронно выставляющий класс `dark` на `<html>`.
- **Избегать**: Тяжелых React Context провайдеров или скриптов после `<body>`, вызывающих белую вспышку при загрузке.

### 2. Плавная прокрутка (Smooth Scroll)

- **Решение**: CSS `html { scroll-behavior: smooth; }` и `scroll-padding-top` с учетом высоты фиксированного хедера.
- **Мобильный аспект**: Проверка системного флага:
  ```css
  @media (prefers-reduced-motion: reduce) {
    html {
      scroll-behavior: auto;
    }
  }
  ```
- **Избегать**: Библиотек вроде Lenis/Locomotive Scroll, если пользователем явно не запрошен кастомный inertia-скролл.

### 3. Аккордеон / FAQ / Сворачиваемые списки

- **Решение**: Нативные HTML-элементы `<details>` и `<summary>` со стилизацией через CSS. Плавное раскрытие через CSS Grid (`grid-template-rows: 0fr -> 1fr`) или modern transition `interpolate-size`.
- **Доступность**: Полная доступность с клавиатуры (Enter/Space, фокус) из коробки без кастомного JS.
- **Избегать**: React/Vue компонентов с состоянием `isOpen` для простых текстовых FAQ.

### 4. Всплывающие подсказки и меню (Dropdowns / Tooltips)

- **Решение**: Modern CSS Popover API (`popover`, `popovertarget`) либо чистый CSS `:focus-within` / `:hover`.
- **Мобильный аспект**: На мобильных устройствах hover не работает, поэтому интерактив строится через клик/тап с нативным Popover API или диалогом.

### 5. Модальные окна

- **Решение**: Нативный тег `<dialog>` с методами `dialog.showModal()` и `dialog.close()`. Нативный фокус-трап и закрытие по `Escape` бесплатно из браузера.
- **Избегать**: Громоздких модальных библиотек весом 20-40 Кб.

### 6. Слайдеры и карусели

- **Решение**: CSS Scroll Snap (`scroll-snap-type: x mandatory`, `scroll-snap-align: start`) с нативным тач-свайпом на мобильных устройствах и скрытым скроллбаром.
- **Интерактив**: Минимальные кнопки вперед/назад через нативный JS-скрипт (`element.scrollBy({ left: ... })`) без тяжелых библиотек вроде Swiper/Slick.

## Формат отчета `pattern-scout`

Когда запрашивается анализ реализации (`/scout <задача>`), агент формирует компактный отчет:

1. **Сравнение подходов (Бенчмарк)**:
   - _Вариант A (Рекомендуемый)_: Нативный HTML/CSS (вес: 0 Кб JS, a11y из коробки).
   - _Вариант B_: Легковесный нативный JS-остров (Astro script, вес < 1 Кб).
   - _Вариант C_: Остров на UI-фреймворке (React/Vue/Svelte) — обосновать, почему он избыточен либо почему он строго необходим.
2. **Влияние на мобильные устройства**:
   - Потребление ресурсов процессора/памяти при анимации.
   - Отработка Touch-событий vs Mouse-событий.
   - Поведение при медленном 3G-соединении.
3. **Рекомендация и пример сигнатуры**:
   - Краткий сниппет разметки или CSS-структуры для передачи в скилл `astro-architect`.
