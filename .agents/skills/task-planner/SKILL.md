## Обязательная структура плана

План декомпозиции генерируется по следующим разделам:

### 1. Семантическая структура разметки

- Логический тег секции/контейнера (`<section>`, `<article>`, `<header>`, `<nav>`).
- Иерархия заголовков (убедиться, что тег `<h1>` используется строго один раз на страницу в Hero, во всех остальных секциях — `<h2>`, `<h3>`).
- Семантические интерактивные элементы (`<button type="button">`, `<a href="...">`).
- Спецификация изображений и иконок (только через `astro:assets` с обязательными `alt`, `width`, `height`).

### 2. Интерфейс входных данных (TypeScript Props)

- Описание интерфейса пропсов без реализации самого компонента:
  ```typescript
  interface Props {
    title: string;
    description?: string;
    // Типизация всех входных параметров
  }
  ```
- Определение дефолтных значений или слотов Astro (`<slot />`).

### 3. Состояния и необходимость клиентских островов

- Анализ: можно ли реализовать задачу на 100% статично в `.astro` (Zero JS)?
- Если требуется интерактив:
  - Можно ли решить нативно через HTML/CSS (например, `<details>/<summary>`, CSS popover, `:checked`, CSS scroll-behavior)?
  - Если требуется остров на UI-фреймворке: точное обоснование и предварительный выбор директивы (`client:visible`, `client:idle`, либо `client:load` только для Hero).

### 4. Desktop-First сетка и глубокая проработка мобильного поведения

> [!IMPORTANT]
> Базовая верстка планируется по принципу **Desktop-First**, однако адаптивность под планшеты и мобильные устройства требует детальной предварительной проработки:

- **Перестройка компоновки (Layout Breakpoints)**:
  - Как трансформируется desktop-сетка (CSS Grid / Flex) на планшетах (`<=1024px`, `<=768px`) и смартфонах (`<=480px`): переход в одноколоночный стек, горизонтальный скролл с прилипанием (`scroll-snap`), модальные шторки (drawer) вместо всплывающих меню.
- **Поведение и анимации на Mobile**:
  - **Сложные анимации**: детально продумать деградацию или адаптацию тяжелых desktop-анимаций (курсорные эффекты, parallax, 3D-tilt, многослойный canvas/WebGL). На мобильных устройствах они должны либо упрощаться до легких CSS-трансформаций (`opacity`, `transform`), либо отключаться для экономии батареи и CPU.
  - **Touch-взаимодействия**: замена desktop hover-эффектов на touch/tap состояния, обеспечение минимального размера кликабельных областей (не менее `44x44px` по WCAG).
  - **Защита от сдвигов верстки (CLS)**: жесткая фиксация пропорций (aspect-ratio) для карточек, медиа и слайдеров, чтобы избежать дергания контента при загрузке на мобильном интернете.
  - **Горизонтальный скролл**: гарантировать отсутствие случайного переполнения экрана (`overflow-x: hidden` / проверка отрицательных марджинов и абсолютных элементов).
  - **Учет системных настроек**: обязательная поддержка `@media (prefers-reduced-motion: reduce)`.

### 5. Чеклист дизайн-токенов из `DESIGN.md`

- Список необходимых цветов (фон, текст, акценты, бордеры).
- Список типографических классов.
- Список внешних и внутренних отступов (padding/margin) и радиусов.

### 6. Вопросы и неопределенности

- Список вопросов пользователю по недостающим текстам, иконкам, вариантам отображения или крайним состояниям (empty state, error state).
