# Скилл: design-enforcer (Стилизация по дизайн-токенам)

Скилл контролирует точное соответствие стилей проектной дизайн-системе [DESIGN.md](file:///c:/Users/Admin/WebstormProjects/portfolio/DESIGN.md) и предотвращает накопление визуального техдолга.

---

## 🚫 ЖЕСТКИЕ ЗАПРЕТЫ (ZERO-TOLERANCE)

> [!CAUTION]
> **ЗАПРЕЩЕНО ИСПОЛЬЗОВАТЬ ПРОИЗВОЛЬНЫЕ ("МАГИЧЕСКИЕ") ЗНАЧЕНИЯ:**
>
> 1. **Никаких ad-hoc отступов**: Запрещены классы вида `p-[17px]`, `mt-[23px]`, `gap-[11px]` или inline-стили `margin: 19px`. Отступы берутся **исключительно** из шкалы спейсингов дизайн-системы (например, `4, 8, 12, 16, 24, 32, 48, 64px`).
> 2. **Никаких случайных цветов**: Запрещено использовать произвольные HEX-коды (`#3a3a3a`) или случайные оттенки палитры (`text-zinc-400`, `bg-gray-100`), если в дизайн-системе зафиксированы семантические токены (`text-muted-foreground`, `bg-background`, `border-border`, `--color-primary`).
> 3. **Никаких случайных радиусов**: Скругления должны строго использовать токены `rounded-sm`, `rounded-md`, `rounded-lg`, `rounded-full` (или соответствующие CSS-переменные `--radius-*`).

## 🖥️ Desktop-First подход и правила адаптивности

Верстка строится от десктопной композиции к мобильной с обязательным соблюдением следующих стандартов:

### 1. Десктопная основа (Baseline)

- Сетки (CSS Grid, Flexbox) и контейнеры (`max-w-*`, `container`) проектируются для комфортного отображения на разрешениях от `1200px` до `1920px`.
- Базовые размеры типографики и интервалов соответствуют спецификации десктопа в `DESIGN.md`.

### 2. Адаптация под планшеты и смартфоны

- При уменьшении экрана (через `@media (max-width: ...)`):
  - Многоколоночные сетки плавно перестраиваются в стек (`grid-cols-1`) либо в горизонтальную ленту со `scroll-snap`.
  - Отступы секций пропорционально масштабируются (например, `py-20` на десктопе -> `py-10` на мобильных).
  - Строгий контроль переполнения: на мобильных устройствах недопустим горизонтальный скролл (`overflow-x`). Никаких выходящих за экран абсолютных элементов без маскирования.

### 3. Поведение сложных анимаций на мобильных устройствах

- **Разделение мыши и тача**:
  - Анимации, привязанные к координатам курсора (`mousemove`, 3D-card tilt, custom cursor, magnetic buttons), должны быть **полностью отключены** на touch-устройствах (`@media (hover: none)`).
  - Hover-эффекты (подъем карточки, появление оверлея) заменяются на активные состояния (`:active`) или постоянную видимость ключевого контента.
- **Оптимизация производительности анимаций**:
  - Для мобильных браузеров разрешено анимировать только свойства композитинга: `transform` и `opacity`. Никаких анимаций `width`, `height`, `top`, `filter: blur(...)` на мобильных экранах во избежание просадки FPS.
- **Reduced Motion**:
  - Обязательное правило доступности:
    ```css
    @media (prefers-reduced-motion: reduce) {
      *,
      *::before,
      *::after {
        animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important;
        transition-duration: 0.01ms !important;
        scroll-behavior: auto !important;
      }
    }
    ```

### 4. Доступность сенсорного ввода (Touch Targets)

- Любой интерактивный элемент (кнопка, ссылка, чекбокс, иконка закрытия) на мобильном экране должен иметь активную область нажатия **не менее 44x44 CSS-пикселей**.

## 🔍 Процесс проверки стилизации

При ревью или стилизации компонента агент сверяет каждый селектор:

1. Откуда взят цвет фона и текста? (Сверить с палитрой `DESIGN.md`).
2. Соответствует ли размер шрифта и межстрочный интервал типографической шкале?
3. Проверено ли отображение на узких экранах (`320px`, `375px`, `768px`)?
4. Нет ли «плавающих» пикселей и несогласованных радиусов?
