# Справочник конфигурации Astro (`astro.config.mjs`)

Полный структурированный обзор параметров конфигурации Astro на основе официальной документации ([Astro Configuration Reference](https://docs.astro.build/en/reference/configuration-reference/)).

Справочник актуален для последних версий Astro (включая нововведения версий 5.x, 6.x и 7.x) и содержит рекомендации по применению в контексте SSG / Cloudflare Pages.

---

## 1. Основные параметры (Top-Level Options)

### `site`
- **Тип:** `string`
- **Назначение:** Полный публичный URL развернутого сайта (например, `https://qwerty0zero.pages.dev`).
- **Зачем нужен:** Критически важен для SEO: на его основе формируются абсолютные канонические ссылки (`canonical URLs`), карта сайта (`@astrojs/sitemap`) и Open Graph теги.
- **Рекомендация:** Всегда указывать для продакшена.

### `base`
- **Тип:** `string`
- **Назначение:** Базовый путь подкаталога, если сайт разворачивается не в корне домена (например, `'/docs'`).
- **Особенности:** Доступен в коде через `import.meta.env.BASE_URL`. Слэш в конце вычисляется согласно настройке `trailingSlash`.

### `trailingSlash`
- **Тип:** `'always' | 'never' | 'ignore'`
- **По умолчанию:** `'ignore'`
- **Назначение:** Политика завершающего слэша (`/`) в URL страниц:
  - `'ignore'` — совпадение маршрута происходит независимо от наличия слэша.
  - `'always'` — URL всегда должен заканчиваться слэшем (`/about/`). Запросы без слэша редиректятся на URL со слэшем.
  - `'never'` — URL не должен содержать завершающий слэш (`/about`).
- **Рекомендация для Cloudflare Pages / SSG:** Согласовывать со стратегией платформы и `build.format`. Для предотвращения цепочек 308-редиректов на CDN рекомендуется явная фиксация (`'never'` или `'always'`).

### `redirects`
- **Тип:** `Record<string, RedirectConfig>`
- **По умолчанию:** `{}`
- **Назначение:** Карта правил перенаправления (редиректов). Ключ — исходный путь, значение — целевой адрес или объект с настройками:
  ```js
  redirects: {
    '/old-path': '/new-path',
    '/external': 'https://example.com',
    '/legacy': { status: 302, destination: '/modern' }
  }
  ```
- **Особенности:** В статическом режиме (`output: 'static'`) без адаптера Astro генерирует клиентские редиректы через `<meta http-equiv="refresh">`. С адаптером (например, Cloudflare) генерируются платформенные правила (например, файл `_redirects`) со статусами 301/308.

### `output`
- **Тип:** `'static' | 'server'`
- **По умолчанию:** `'static'`
- **Назначение:** Режим сборки проекта:
  - `'static'` — полная статическая генерация (SSG). Все страницы предварительно рендерятся в HTML при сборке.
  - `'server'` — серверный рендеринг по умолчанию (SSR). Требует подключения адаптера (`adapter`).

### `adapter`
- **Тип:** `AstroIntegration`
- **Назначение:** Адаптер целевой платформы для поддержки SSR, Server Actions и динамического рендеринга (`@astrojs/cloudflare`, `@astrojs/node`, `@astrojs/vercel`, `@astrojs/netlify`).
- **Особенности:** Для чистого SSG адаптер не обязателен, но может использоваться для интеграции со специфичными фичами платформы хостинга.

### `integrations`
- **Тип:** `AstroIntegration[]`
- **По умолчанию:** `[]`
- **Назначение:** Подключение плагинов и расширений Astro:
  - UI-библиотеки: React, Vue, Svelte, Solid;
  - Функционал: `@astrojs/sitemap`, `@astrojs/mdx`, Tailwind и др.

### `root`
- **Тип:** `string` (CLI: `--root`)
- **По умолчанию:** `"."` (текущая рабочая директория)
- **Назначение:** Корневая папка проекта, где Astro ищет файлы конфигурации и зависимости.

### `srcDir`
- **Тип:** `string`
- **По умолчанию:** `"./src"`
- **Назначение:** Папка с исходным кодом проекта (компоненты, страницы, стили, контент).

### `publicDir`
- **Тип:** `string`
- **По умолчанию:** `"./public"`
- **Назначение:** Папка для необрабатываемых статичных файлов (фавиконы, `robots.txt`, шрифты). Файлы отсюда копируются в корень сборки без бандлинга и хеширования.

### `outDir`
- **Тип:** `string`
- **По умолчанию:** `"./dist"`
- **Назначение:** Целевая папка для сохранения готовой сборки сайта.

### `cacheDir`
- **Тип:** `string`
- **По умолчанию:** `"./node_modules/.astro"`
- **Назначение:** Папка внутреннего кэша Astro (кэширование сборки, оптимизированных изображений, Content Layer).

### `compressHTML`
- **Тип:** `boolean`
- **По умолчанию:** `true`
- **Назначение:** Минификация сгенерированного HTML-кода при сборке (удаление лишних пробелов, переносов строк, комментариев). Уменьшает вес страниц.

### `scopedStyleStrategy`
- **Тип:** `'where' | 'class' | 'attribute'`
- **По умолчанию:** `'where'`
- **Назначение:** Способ изоляции стилей (CSS Scoping) в `.astro` компонентах:
  - `'where'` — использует псевдокласс `:where(.astro-xxxx)`. Не повышает CSS-специфичность селекторов, позволяя легко переопределять стили извне.
  - `'class'` — использует обычный класс `.astro-xxxx` (повышает специфичность на +1 класс).
  - `'attribute'` — добавляет HTML-атрибут `data-astro-cid-xxxx`.

### `prerenderConflictBehavior`
- **Тип:** `'throw' | 'warn' | 'ignore'`
- **По умолчанию:** `'throw'`
- **Назначение:** Реакция Astro на конфликт маршрутов (когда статический маршрут совпадает с динамическим SSR-роутом).

### `vite`
- **Тип:** `ViteUserConfig`
- **Назначение:** Проброс кастомных параметров напрямую в сборщик Vite: алиасы путей (`resolve.alias`), плагины Rollup/Vite, препроцессоры CSS, настройки оптимизации зависимостей (`optimizeDeps`).

### `security`
- **Тип:** `object`
- **Назначение:** Настройки веб-безопасности:
  - `security.checkOrigin` (`boolean`, по умолчанию `true`): Проверка заголовка `Origin` для форм (`POST`) и Astro Actions для предотвращения CSRF-атак.
  - `security.csp` (`object`, с версии v6.0.0): Автоматическая генерация тегов Content Security Policy (CSP):
    - `algorithm` (`'sha256' | 'sha384' | 'sha512'`): алгоритм хеширования встроенных скриптов;
    - `reportOnly` (`boolean`): режим только отчетов без блокировки;
    - `directives` (`Record<string, string[]>`): кастомные директивы CSP;
    - `scriptDirective.resources` (`Array<string | CspResourceEntry>`): разрешенные источники скриптов;
    - `scriptDirective.strictDynamic` (`boolean`): активация ключевого слова `'strict-dynamic'`.

## 2. Параметры сборки (`build.*`)

### `build.format`
- **Тип:** `'directory' | 'file' | 'preserve'`
- **По умолчанию:** `'directory'`
- **Назначение:** Структура генерируемых HTML-файлов:
  - `'directory'` — для каждой страницы создается подпапка с `index.html` (например, `/about/index.html`). URL страниц будут иметь вид `/about/`.
  - `'file'` — страницы генерируются в виде плоских HTML-файлов (например, `/about.html`).
  - `'preserve'` — сохраняет точную файловую структуру исходников (например, `src/pages/about.astro` компилируется в `about.html`, а `src/pages/contact/index.astro` — в `contact/index.html`).

### `build.client`
- **Тип:** `string`
- **По умолчанию:** `'./client'`
- **Назначение:** Путь к папке клиентских ассетов относительно `outDir` при сборке в режиме SSR (`output: 'server'`).

### `build.server`
- **Тип:** `string`
- **По умолчанию:** `'./server'`
- **Назначение:** Путь к папке серверного кода относительно `outDir` при сборке в режиме SSR.

### `build.assets`
- **Тип:** `string`
- **По умолчанию:** `'_astro'`
- **Назначение:** Название папки в выходном билде, куда складываются скомпилированные бандлы JS, CSS и оптимизированные изображения.

### `build.assetsPrefix`
- **Тип:** `string | Record<string, string>`
- **По умолчанию:** `undefined`
- **Назначение:** Префикс CDN для подключаемых скомпилированных ассетов. Можно указать строковый URL (например, `https://cdn.example.com`) или объект распределения по типам файлов с обязательным полем `fallback`.

### `build.serverEntry`
- **Тип:** `string`
- **По умолчанию:** `'entry.mjs'`
- **Назначение:** Имя файла точки входа серверного приложения для автономных серверов SSR (например, Node.js standalone).

### `build.redirects`
- **Тип:** `boolean`
- **По умолчанию:** `true`
- **Назначение:** Выводить ли платформенные файлы редиректов (например, `_redirects` для Cloudflare/Netlify) при сборке.

### `build.inlineStylesheets`
- **Тип:** `'always' | 'auto' | 'never'`
- **По умолчанию:** `'auto'`
- **Назначение:** Политика инлайнинга CSS прямо в тег `<style>` внутри HTML:
  - `'auto'` — автоматически инлайнит небольшие CSS-файлы (размером меньше порога Vite `assetsInlineLimit`, по умолчанию 4 КБ). Стили больше этого размера подключаются через внешний `<link rel="stylesheet">`.
  - `'always'` — все стили инлайнятся в HTML (устраняет лишние HTTP-запросы стилей, ускоряет FCP на небольших страницах).
  - `'never'` — все стили подключаются через внешние файлы.

### `build.concurrency`
- **Тип:** `number`
- **По умолчанию:** `1`
- **Назначение:** Число параллельно рендерящихся страниц при статической сборке. Увеличение ускоряет билд больших сайтов на многоядерных процессорах.

## 3. Параметры локального сервера (`server.*`)

### `server.host`
- **Тип:** `string | boolean`
- **По умолчанию:** `false`
- **Назначение:** IP-адрес для прослушивания локального dev-сервера. Значение `true` или `'0.0.0.0'` открывает доступ к серверу по локальной сети (для тестирования с мобильных устройств).

### `server.port`
- **Тип:** `number`
- **По умолчанию:** `4321`
- **Назначение:** Порт локального сервера разработки.

### `server.allowedHosts` *(Astro 5.4+)*
- **Тип:** `Array<string> | true`
- **По умолчанию:** `[]`
- **Назначение:** Список разрешенных имен хостов (hostnames) для защиты от DNS rebinding атак при использовании туннелей (ngrok, cloudflared) или реверс-прокси. Значение `true` разрешает любые хосты.

### `server.open`
- **Тип:** `string | boolean`
- **По умолчанию:** `false`
- **Назначение:** Автоматически открывать сайт в браузере при запуске `astro dev`. Можно передать конкретный путь (например, `'/about'`).

### `server.headers`
- **Тип:** `OutgoingHttpHeaders`
- **По умолчанию:** `{}`
- **Назначение:** Кастомные HTTP-заголовки для ответов локального сервера разработки и `astro preview` (например, CORS, заголовки безопасности).

## 4. Пайплайн обработки запросов (`fetchFile`) *(Astro 7.0+)*

### `fetchFile`
- **Тип:** `string | null`
- **По умолчанию:** `'fetch'`
- **Назначение:** Указывает имя файла точки входа внутри `srcDir` (по умолчанию ищется `src/fetch.ts` / `.js`), позволяющего перехватывать и композировать низкоуровневый пайплайн обработки веб-запросов Astro со стандартом Web Fetch или middleware фреймворков вроде Hono. Значение `null` отключает данный механизм.

## 5. Параметры логирования (`logger.*`) *(Astro 7.0+)*

### `logger`
- **Тип:** `LoggerHandlerConfig`
- **По умолчанию:** `undefined`
- **Назначение:** Позволяет переопределить форматирование и вывод системных логов Astro (например, включить структурированный JSON-логгер для продакшена: `logHandlers.json({ level: 'info' })`).

### `logger.entrypoint`
- **Тип:** `string | URL`
- **Назначение:** Путь к кастомному JS-модулю реализации логера.

### `logger.config`
- **Тип:** `Record<string, unknown>`
- **По умолчанию:** `{}`
- **Назначение:** Параметры конфигурации, передаваемые в кастомный или встроенный логер.

---

## 6. Параметры сессий (`session.*`) *(Astro 5.7+ / 7.2+)*

### `session`
- **Тип:** `object | false`
- **Назначение:** Встроенная система серверных сессий для сохранения состояния пользователей между запросами.
- **Особенности:** Начиная с Astro v7.2.0 можно указать `session: false` — это полностью исключает рантайм сессий из бандла, что снижает время холодного старта в Serverless/Edge окружениях.

### `session.driver`
- **Тип:** `SessionDriverConfig`
- **Назначение:** Драйвер хранилища сессий (Redis, Cloudflare KV, Cookie, Memory и др. на базе экосистемы Unstorage).

### `session.cookie`
- **Тип:** `string | AstroCookieSetOptions`
- **По умолчанию:** `{ name: "astro-session", sameSite: "lax", httpOnly: true, secure: true }`
- **Назначение:** Конфигурация session-cookie (имя, параметры безопасности).

### `session.ttl`
- **Тип:** `number`
- **Назначение:** Глобальное время жизни значений сессии в секундах (Time-To-Live).

## 7. Панель разработчика (`devToolbar.*`)

### `devToolbar.enabled`
- **Тип:** `boolean`
- **По умолчанию:** `true`
- **Назначение:** Включение/отключение панели инструментов Astro Dev Toolbar на уровне проекта в режиме разработки.

### `devToolbar.placement` *(Astro 5.17+)*
- **Тип:** `'bottom-left' | 'bottom-center' | 'bottom-right'`
- **По умолчанию:** `'bottom-center'`
- **Назначение:** Стартовое положение тулбара на экране браузера.

## 8. Параметры предзагрузки (`prefetch.*`)

### `prefetch`
- **Тип:** `boolean | object`
- **Назначение:** Автоматическое внедрение скрипта упреждающей загрузки (prefetching) страниц при наведении или появлении ссылок во viewport. Значительно ускоряет переход между страницами.

### `prefetch.prefetchAll`
- **Тип:** `boolean`
- **По умолчанию:** `true` при использовании `<ClientRouter />`, иначе `false`
- **Назначение:** Предзагрузка всех ссылок на странице без необходимости явно указывать атрибут `data-astro-prefetch`.

### `prefetch.defaultStrategy`
- **Тип:** `'tap' | 'hover' | 'viewport' | 'load'`
- **По умолчанию:** `'hover'`
- **Назначение:** Стратегия предзагрузки по умолчанию:
  - `'hover'` — при наведении курсора или фокусе ссылки;
  - `'tap'` — в момент касания/нажатия перед переходом;
  - `'viewport'` — когда ссылка появляется в зоне видимости экрана;
  - `'load'` — загрузка всех ссылок страницы сразу после завершения загрузки документа.

## 9. Оптимизация изображений (`image.*`)

### `image.endpoint`
- **Тип:** `Object`
- **По умолчанию:** `{ route: '/_image', entrypoint: undefined }`
- **Назначение:** Эндпоинт для трансформации изображений на лету в режимах dev и SSR.

### `image.service`
- **Тип:** `Object`
- **По умолчанию:** `{ entrypoint: 'astro/assets/services/sharp', config: {} }`
- **Назначение:** Движок обработки изображений:
  - По умолчанию используется `Sharp`.
  - В `image.service.config` настраиваются параметры компрессии (`webp`, `jpeg`, `avif`, `png`), фильтрация ресайза (`kernel`) и снятие лимита размера (`limitInputPixels: false`).

### `image.dangerouslyProcessSVG` *(Astro 6.3+)*
- **Тип:** `boolean`
- **По умолчанию:** `false`
- **Назначение:** Разрешение обработки векторных SVG-изображений через общий графический пайплайн. Отключено по умолчанию из соображений безопасности (защита от XML/SVG DoS-атак).

### `image.domains`
- **Тип:** `Array<string>`
- **По умолчанию:** `[]`
- **Назначение:** Белый список внешних доменов, изображения с которых разрешено оптимизировать компонентом `<Image />`.

### `image.remotePatterns`
- **Тип:** `Array<RemotePattern>`
- **По умолчанию:** `[]`
- **Назначение:** Тонкая настройка разрешенных удаленных адресов изображений по протоколу, хосту, порту и маске пути (поддерживает wildcards `**`).

### `image.responsiveStyles` *(Astro 5.x+)*
- **Тип:** `boolean`
- **По умолчанию:** `true`
- **Назначение:** Автоматическая генерация инлайн-стилей для обеспечения адаптивности элементов `<Image />` и `<Picture />`.

### `image.layout`
- **Тип:** `'responsive' | 'fixed' | 'full-width' | 'none'`
- **Назначение:** Дефолтная раскладка (layout) для изображений проекта.

### `image.objectFit`
- **Тип:** `'cover' | 'contain' | 'fill' | 'none' | 'scale-down'`
- **По умолчанию:** `'cover'`
- **Назначение:** Дефолтное CSS-свойство `object-fit` для адаптивных картинок.

### `image.objectPosition`
- **Тип:** `string`
- **По умолчанию:** `'center'`
- **Назначение:** Дефолтное CSS-свойство `object-position` (позиционирование фокуса кадрирования).

### `image.breakpoints`
- **Тип:** `Array<number>`
- **Назначение:** Набор ширин экранов (брейкпоинтов) для генерации атрибута `srcset` отзывчивых изображений.

## 10. Обработка Markdown (`markdown.*`)

### `markdown.shikiConfig`
- **Тип:** `Partial<ShikiConfig>`
- **Назначение:** Конфигурация встроенного подсветчика синтаксиса Shiki:
  - `theme` / `themes`: выбор темы оформления (например, `{ light: 'github-light', dark: 'github-dark' }`);
  - `defaultColor`: отключение стандартных цветов при использовании дуальных тем;
  - `langs` / `langAlias`: регистрация редких языков или синонимов;
  - `wrap`: перенос длинных строк кода для предотвращения горизонтального скролла;
  - `transformers`: подключение плагинов-трансформеров Shiki (например, подсветка строк, номеров строк).

### `markdown.syntaxHighlight`
- **Тип:** `'shiki' | 'prism' | false | SyntaxHighlightConfig`
- **По умолчанию:** `{ type: 'shiki', excludeLangs: ['math'] }`
- **Назначение:** Выбор движка подсветки синтаксиса: Shiki, Prism или полное отключение. Поддерживает свойство `excludeLangs` для исключения блоков кода (например, `mermaid`, диаграмм).

### `markdown.processor` *(Astro 6.4+)*
- **Тип:** `MarkdownProcessor`
- **Назначение:** Выбор и настройка движка рендеринга Markdown:
  - По умолчанию используется `Sätteri` (нативный сверхбыстрый движок Astro, конфигурируется через `satteri()`).
  - Поддерживается переключение на классический процессор `unified()`.

### `markdown.remarkPlugins`, `markdown.rehypePlugins`, `markdown.gfm`, `markdown.smartypants`, `markdown.remarkRehype`
- **Статус:** *Устарели (Deprecated)* начиная с Astro v6.4.
- **Примечание:** В современных версиях Astro плагины Remark/Rehype, опции GFM и SmartyPants передаются напрямую внутрь выбранного процессора `markdown.processor: satteri({ ... })` или `unified({ ... })`.

## 11. Интернационализация (`i18n.*`)

### `i18n.locales`
- **Тип:** `Array<string | Locale>`
- **Назначение:** Список поддерживаемых языков сайта (например, `['ru', 'en', 'pl', 'uk']`). Может содержать объекты для настройки альтернативных путей или кодов.

### `i18n.defaultLocale`
- **Тип:** `string`
- **Назначение:** Основной язык по умолчанию (например, `'ru'`).

### `i18n.fallback`
- **Тип:** `Record<string, string>`
- **Назначение:** Словарь сопоставления фоллбэков при отсутствии перевода:
  ```js
  fallback: {
    fr: 'en',
    pl: 'en'
  }
  ```

### `i18n.routing`
- **Тип:** `'manual' | object`
- **Назначение:** Стратегия маршрутизации:
  - `prefixDefaultLocale` (`boolean`, по умолчанию `false`): добавлять ли префикс для языка по умолчанию (`/ru/about` против `/about`).
  - `redirectToDefaultLocale` (`boolean`, по умолчанию `false`): перенаправлять ли с корня `/` на `/[defaultLocale]`, если включен префикс дефолтного языка.
  - `fallbackType` (`'redirect' | 'rewrite'`, по умолчанию `'redirect'`, Astro 4.15+):
    - `'redirect'` — браузер физически перенаправляется на язык-фоллбэк со сменой адреса в URL-строке;
    - `'rewrite'` — контент страницы-фоллбэка отдается по исходному запрошенному URL без изменения адреса и без редиректа.
  - `'manual'` — полное отключение встроенного роутинг-middleware для написания собственной логики маршрутизации.

### `i18n.domains`
- **Тип:** `Record<string, string>`
- **По умолчанию:** `{}`
- **Назначение:** Привязка локалей к отдельным доменным именам или субдоменам:
  ```js
  domains: {
    pl: 'https://pl.example.com',
    en: 'https://example.com'
  }
  ```

## 12. Типобезопасные переменные окружения (`env.*`) *(Astro 5.0+)*

### `env.schema`
- **Тип:** `EnvSchema`
- **По умолчанию:** `{}`
- **Назначение:** Декларативное описание схемы переменных окружения через хелпер `envField`:
  ```js
  import { envField } from 'astro/config';

  export default defineConfig({
    env: {
      schema: {
        PUBLIC_API_URL: envField.string({ context: 'client', access: 'public', optional: true }),
        DATABASE_PORT: envField.number({ context: 'server', access: 'public', default: 5432 }),
        SECRET_TOKEN: envField.string({ context: 'server', access: 'secret' }),
      }
    }
  });
  ```
- **Преимущества:** Полная типобезопасность (TypeScript autocompletion), валидация значений при запуске и изоляция серверных секретов от клиента.

### `env.validateSecrets`
- **Тип:** `boolean`
- **По умолчанию:** `false`
- **Назначение:** Валидация секретных серверных переменных уже на этапе сборки и старта dev-сервера (по умолчанию секреты проверяются только в рантайме). Рекомендуется включать в CI/CD пайплайнах.

## 13. Управление шрифтами (`fonts.*`) *(Astro 6.0+)*

Встроенная подсистема загрузки и оптимизации веб-шрифтов.

### `fonts`
- **Тип:** `Array<FontFamily>`
- **По умолчанию:** `[]`
- **Назначение:** Описание подключаемых шрифтов:
  - `font.provider` (`FontProvider`): источник шрифта (Google Fonts, Fontsource, локальные файлы);
  - `font.name` (`string`): наименование шрифтового семейства (например, `'Inter'`);
  - `font.cssVariable` (`string`): имя генерируемой CSS-переменной (например, `'--font-inter'`);
  - `font.fallbacks` (`string[]`): стек запасных шрифтов;
  - `font.optimizedFallbacks` (`boolean`): автоматическая генерация скорректированных метрик фоллбэк-шрифтов для полного устранения сдвигов макета (CLS);
  - `font.weights`, `font.styles`, `font.subsets`, `font.formats`: веса, начертания и сабсеты (например, `['cyrillic', 'latin']`);
  - `font.display`: свойство `font-display` (`'swap'`, `'optional'`, `'block'` и др.);
  - `font.unicodeRange`, `font.stretch`, `font.featureSettings`, `font.variationSettings`: тонкие параметры рендеринга шрифтов.

## 14. Кэширование ответов (`cache.*`, `routeRules`) *(Astro 7.0+)*

### `cache.provider`
- **Тип:** `CacheProviderConfig`
- **Назначение:** Провайдер серверного кэша ответов (например, `memoryCache()`).

### `routeRules`
- **Тип:** `Record<string, RouteRule>`
- **Назначение:** Декларативные правила кэширования для маршрутов:
  ```js
  routeRules: {
    '/api/[...path]': { swr: 600 },
    '/projects/[...slug]': { maxAge: 3600, tags: ['projects'] }
  }
  ```
- **Параметры:** `maxAge` (время кэширования в секундах), `swr` (Stale-While-Revalidate), `tags` (теги для точечной инвалидации кэша через API).

## Резюме: ключевые настройки для SSG / Cloudflare Pages

Для статического портфолио на Cloudflare Pages с многоязычностью наиболее критичны следующие параметры:

1. **`site`**: Указать продакшен URL (`https://qwerty0zero.pages.dev` или собственный домен) для корректных canonical URLs и sitemap.
2. **`output: 'static'`**: Режим чистой статической генерации (Zero JS by default).
3. **`trailingSlash: 'never'` (или `'always'`)**: Согласовать с настройками Cloudflare Pages, чтобы избежать скрытых 308-редиректов на CDN.
4. **`compressHTML: true`**: Максимальное сжатие HTML для быстрой загрузки.
5. **`build.inlineStylesheets: 'auto'`**: Оптимальный баланс — критические стили маленького размера попадают в HTML, большие файлы кэшируются браузером отдельно.
6. **`scopedStyleStrategy: 'where'`**: Позволяет гибко переопределять стили компонентов без борьбы со специфичностью селекторов.
7. **`i18n`**: Тонкая настройка языков (`locales`, `defaultLocale`, `routing`).
